1. Current workflow assessment — Exploratory

Due Sep 7 Complete Christopher W. · Daniel H.

Current production workflow (WTV today)

External mix via Polarity Audioworks on a ~22:30 episode. Times are editor-side unless noted.

#StepEst. timeNotes
1Nest any remixed music<5 minRequired to prevent an AAF export glitch
2Export AAF15–20 minHandoff package for external post
3Upload AAF to Dropbox5–10 min
4Email Polarity Audioworks with Dropbox link—Vendor turnaround not included below
5Download / import new audio streams into Premiere; mute existing5–10 minRe-alignment against locked picture
6QAQC~30 minPer 22:30 episode

Revision loop (when QAQC fails)

  1. Send back to Polarity with fix notes (vendor turnaround).
  2. Re-import returned streams and QAQC again — 15–20 min per revision cycle.
Editor-side time (happy path, excluding vendor) ~60–75 min per episode before Polarity’s work. Each failed QAQC adds at least one more 15–20 min re-import/QAQC pass, plus another vendor round trip.

Pain points this flow creates

  • Vendor dependency — every episode waits on Polarity + email/Dropbox handoff.
  • AAF round-trip — export, upload, re-import; nesting workaround for music glitches.
  • Revision cost — failed QAQC doubles down on import + 30 min review (or 15–20 min on revision pass).
  • No in-timeline iteration — can’t audition a duck or dialogue fix without another full cycle.

Proposed in-panel workflow

Connect→ Options→ 1 Prepare→ 2 Clean→ 3 Add tracks→ 4 Duck music
Fix a pop Enhance low end (optional branches)

Validated in real use (Sep 9–11)

  • Native music ducking
  • Per-clip Prepare → Clean → Add tracks
  • Dialogue dynamics + de-ess chain
  • Music pass (422 silent-music fix)
  • Partial dialogue selection

Still open

  • Fix a pop + Enhance low end native acceptance
  • Workflow review items 4–9
  • Mac service path (panel likely portable)
  • GPU per editor vs shared service economics
Conclusion The Polarity AAF round-trip (~60–75 min editor time per episode, plus vendor latency and revision loops) is the main cost driver WTVAudioWizard targets. In-Premiere cleanup + ducking removes export/upload/email/re-import for those steps and keeps QAQC inside the same timeline.

3. End goal, capabilities & schema — NEEDS

Due Sep 8 Complete Christopher W. · Daniel H. · Shane A.

End goal

One local AI-assisted audio post panel that:

  1. Cleans dialogue inside a Premiere clone.
  2. Optionally extracts ambience/music stems without replacing timeline music.
  3. Finishes existing music with baseline + dialogue-triggered ducking.
  4. Offers pop fix and whisper body boost without full re-clean.
  5. Preserves non-destructive editorial workflow.
  6. Runs on macOS as well as Windows (Premiere panel + local GPU service).

5. Plan before any code is written

Due Sep 10 Complete Daniel H.

Retrospective plan record. Code exists at v0.7.1 and aligns with this architecture.

Architecture

┌─────────────────────┐         token/HTTP          ┌──────────────────────┐
│  Premiere UXP panel │ ◄──────────────────────────► │  Local Python service │
│  plugin/*.js        │    assets · jobs · analysis  │  service/*.py · GPU   │
└─────────┬───────────┘                              └──────────┬───────────┘
          │ clone / export / import                               │ one GPU job
          ▼                                                       ▼
   Premiere Project                                     work/wtv-data · stage-cache

Design principles

  1. Never replace raw clips — add aligned stems in a clone.
  2. Bandit speech never feeds dialogue cleanup.
  3. Timeline music finished with native effects, not extracted stems.
  4. Upload once; refer by asset_id.
  5. One GPU model resident; idle unload.
  6. Immutable stage cache keyed by audio + checkpoint identity.
  7. Verify timeline before/after; Copy report on failure.
